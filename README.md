## HW3. Моделирование гостиницы с помощью процессов

**Выполнил:** Татарников Максим Александрович, БПИ-252.

**Вариант:** №12 – Задача о гостинице.

**Реализованный уровень:** 4–5 баллов.

### 1. Условие задачи

В гостинице есть ограниченное количество одноместных номеров. Клиенты прибывают через случайные интервалы и запрашивают номер на заданное число суток. Если свободных номеров нет, клиент встаёт в очередь. После выезда одного гостя администратор заселяет следующего.

В консоли отображаются прибытие, ожидание, назначение номера, заселение, каждые завершённые сутки проживания и выезд. Один номер может занимать только один клиент.

### 2. Организация программы

Программа написана на C на основе прошлого задания. Вместо потоков используются отдельные процессы:

| Участник | Что делает |
| --- | --- |
| Родительский процесс | Читает данные, создаёт дочерние процессы через `fork`, отсчитывает условные сутки и сохраняет результат. |
| Процесс администратора | Обрабатывает очередь и назначает свободные номера. |
| Процесс каждого клиента | Запрашивает номер, ожидает заселения, проживает заданный срок и выезжает. |

Сведения о клиентах, номерах и очереди находятся в разделяемой памяти POSIX. Для согласования действий используются именованные POSIX-семафоры: они защищают общие данные и уведомляют участников о событиях. Родитель начинает следующие сутки после обработки событий текущих суток.

### 3. Правила работы

- Время начинается с нуля. Нулевой интервал позволяет нескольким клиентам прибыть одновременно.
- Заселение происходит по очереди (FIFO). При одновременном прибытии порядок определяется тем, кто раньше встал в очередь.
- Очередь рассчитана на всех клиентов.
- Принимаются клиенты, прибывшие строго раньше момента прекращения приёма.
- После закрытия приёма очередь продолжает обслуживаться. Время ожидания не входит в срок проживания.
- Номер назначается только после освобождения. Каждый заселённый клиент проживает весь заказанный срок при обычном завершении программы.

### 4. Ввод и запуск

Программа запрашивает числа в следующем порядке. Их можно вводить с клавиатуры или читать из файла:

| Параметр | Допустимые значения |
| --- | --- |
| Количество номеров | 1–100 |
| Количество клиентов | 1–100 |
| Минимальный интервал прибытия | 0–10000 суток |
| Максимальный интервал прибытия | От минимального до 10000 суток |
| Момент прекращения приёма | 1–10000 суток |
| Задержка между условными сутками | 0–5 реальных секунд |
| Срок проживания каждого клиента | 1–10000 суток |

Из корня репозитория нужно перейти в папку задания:

```sh
cd HW3
```

Сборка на Linux:

```sh
gcc -std=c11 -Wall -Wextra -Wpedantic -pthread hotel.c -o hotel -lrt
```

На macOS команда выполняется без `-lrt`:

```sh
gcc -std=c11 -Wall -Wextra -Wpedantic -pthread hotel.c -o hotel
```

Запуск с вводом с клавиатуры:

```sh
./hotel
```

Запуск с данными из файла:

```sh
./hotel < tests/test_cutoff.txt
```

### 5. Завершение программы

Программа заканчивает работу, когда все принятые клиенты выехали, а остальные уже не могут быть приняты. Если всех успели обслужить раньше закрытия приёма, моделирование завершается досрочно. При наличии очереди оно продолжается и после закрытия.

Для остановки можно нажать Ctrl+C. Также обрабатывается сигнал `SIGTERM`. Родитель завершает дочерние процессы и дожидается их окончания. Семафоры и разделяемая память удаляются при обычном завершении, этих сигналах и обрабатываемых ошибках.

Итоговая статистика выводится в консоль и сохраняется в `hotel.log`. При досрочной остановке она отражает текущее состояние гостиницы. Ошибка ввода завершает программу с сообщением; сбой дочернего процесса приводит к остановке остальных участников.

Коды завершения: `0` – успех, `1` – ошибка, `130` – Ctrl+C, `143` – `SIGTERM`.

### 6. Проверка работы

Для запуска всех тестов из папки `HW3` нужны компилятор и Python 3:

```sh
sh run_tests.sh
```

8 ноября 2026 года на Linux прошли **57 проверок**, на macOS – **56**. Один тест использует `/proc` и выполняется только на Linux.

Проверены очередь, одновременные прибытия и выезды, граница приёма, большие значения, неправильный ввод и остановка по сигналам. Дополнительно проверены ошибки создания процессов и общих ресурсов, запись лога и два параллельных запуска. Тесты также проверяют, что после завершения не остаются дочерние процессы и созданные объекты общей памяти и семафоров.

Примеры результатов:

| Тест | Сутки завершения | Принято | Не принято |
| --- | --- | --- | --- |
| `test_minimum` | 1 | 1 | 0 |
| `test_cutoff` | 5 | 2 | 1 |
| `test_empty` | 3 | 0 | 2 |
| `test_max_rooms` | 1 | 100 | 0 |
| `test_max_queue` | 100 | 100 | 0 |
| `test_max_stay` | 10001 | 2 | 0 |
| `test_max_interval` | 10000 | 0 | 2 |

В `test_cutoff` первый клиент занимает номер с суток 1 до суток 4. Второй ждёт его выезда и проживает с суток 4 до суток 5. Третий прибывает ровно в момент закрытия приёма и не принимается. Итог:

```text
Моделирование завершено на сутках: 5
Всего приняли клиентов: 2.
Полностью завершили проживание: 2.
Не успели принять клиентов: 1.
Ожидают заселения: 0.
Занятых номеров: 0.
```

Вывод каждого теста и его лог сохраняются в папке `HW3/results`. Порядок действий одновременно прибывших клиентов может отличаться между запусками.
