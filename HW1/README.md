## 1. Условие и цель работы

Разработана консольная программа на языке C, которая моделирует работу гостиницы с одноместными номерами. Программа показывает прибытие клиентов, ожидание в очереди, заселение, прожитые сутки и выезд. В подготовленных тестах очередь обслуживается по порядку, а каждый принятый клиент проживает весь заказанный срок.

По условию клиенты прибывают через случайные интервалы и запрашивают номер на заданное число условных суток. Администратор предоставляет свободный номер. Когда все номера заняты, клиент ждёт в общей очереди. После выезда проживающего освободившийся номер получает следующий ожидающий клиент.

При завершении приёма новых клиентов программа должна обслужить уже принятую очередь и дождаться выезда всех проживающих. Один номер может быть занят только одним клиентом, а один клиент может занимать только один номер.

## 2. Правила реализованной модели

Время начинается с нуля и увеличивается на одни условные сутки. Параметр reception_end задаёт момент прекращения приёма. Принимаются только клиенты с временем прибытия меньше reception_end. Прибытие ровно в момент закрытия уже не обрабатывается. Итоговое время моделирования может превышать этот параметр.

Используется стратегия FIFO (First in first out): первым заселяется тот, кто раньше встал в очередь. Клиенты, прибывшие одновременно, обрабатываются по порядку индексов в массиве. Нулевой интервал между прибытиями позволяет нескольким клиентам прийти на одних сутках.

Отдельное ограничение зоны ожидания не вводится. Массив очереди рассчитан на 100 клиентов, что соответствует максимальному числу клиентов всей модели. Свободный номер выбирается первым при просмотре массива rooms. Стратегия FIFO фиксирована в программе и не запрашивается при вводе.

## 3. Представление участников и алгоритм

Программа выполняется в одном процессе и одном потоке. Каждый клиент представлен отдельной структурой Client. Действия администратора выполняются функциями поиска свободного номера, заселения и блоками основного цикла. Самостоятельные участники предметной области моделируются своими данными и действиями последовательно, без создания процессов для каждого клиента.

| Объект | Представление и назначение |
| --- | --- |
| clients | Массив структур: прибытие, срок проживания, время заселения, номер и состояние каждого клиента. |
| rooms | Массив индексов проживающих клиентов. Значение −1 означает свободный номер. |
| queue | Массив индексов ожидающих клиентов; каждый клиент добавляется не более одного раза. |
| head и tail | head указывает на следующего для заселения, tail – на место добавления в очередь. Очередь пуста при head == tail. |

Состояния клиента: NOT_ARRIVED – ещё не принят; WAITING – ожидает номер; LIVING – проживает; LEFT – выехал. Клиенты с прибытием после закрытия приёма остаются в состоянии NOT_ARRIVED и учитываются в числе непринятых.

Интервал между соседними прибытиями вычисляется выражением arrival_min + rand() % (arrival_max - arrival_min + 1) и прибавляется к времени предыдущего прибытия. Для первого клиента отсчёт идёт от нуля. Вызов srand(1) задаёт повторяемую последовательность в рамках одной реализации генератора.

На каждых условных сутках выполняются следующие действия:

1. Просматриваются занятые номера. Прожитый срок равен current_time − check_in_time. Выводится число завершённых суток; при достижении stay_days клиент выезжает.

2. Свободные номера передаются клиентам из очереди в порядке FIFO.

3. Пока приём открыт, обрабатываются все клиенты, прибывшие в текущий момент. При отсутствии номера клиент добавляется в очередь.

4. Подсчитываются занятые номера. Если приём завершён или все клиенты уже приняты, а гостиница и очередь пусты, цикл заканчивается.

5. Иначе выполняется задержка sleep(delay_seconds), после чего время увеличивается на единицу.

Инварианты поддерживаются порядком операций: check_in вызывается только для свободного номера и согласованно обновляет rooms и clients. При выезде обе записи освобождаются. Ожидание в очереди не включается в срок проживания: его отсчёт начинается с фактического заселения.

## 4. Консольный интерфейс и запуск

Ввод выполняется через стандартный поток stdin. Числа рекомендуется вводить по одному на строку. Функция read_int считывает токен через scanf, преобразует его с помощью strtol и проверяет допустимый диапазон и остаток строки.

| Порядок | Параметр | Допустимые значения |
| --- | --- | --- |
| 1 | Количество номеров | 1–100 |
| 2 | Количество клиентов | 1–100 |
| 3 | Минимальный интервал прибытия | 0–10000 суток |
| 4 | Максимальный интервал прибытия | От минимального до 10000 |
| 5 | Момент прекращения приёма | 1–10000 суток |
| 6 | Реальная задержка между шагами | 0–5 секунд |
| 7 и далее | Срок проживания каждого клиента | 1–10000 суток |

Задержка влияет только на скорость показа событий. При значении 0 тесты выполняются без намеренного ожидания. Моделируемое время по-прежнему изменяется на одни сутки за шаг.


Первый вариант запуска ./hotel предназначен для ручного ввода. Перенаправление < подаёт программе числа из файла. Скрипт run_tests.sh компилирует программу и запускает 13 наборов данных: 10 корректных сценариев и 3 случая ошибочного ввода.

### Вывод и завершение

Для каждых суток выводятся события прибытия и запроса номера, постановки в очередь, заселения, завершения очередного периода проживания и выезда. Заселение из очереди сопровождается отдельным сообщением о клиенте и номере.

При нормальном завершении программа возвращает 0 и сохраняет итоговое время, число принятых и непринятых клиентов в hotel.log. Файл создаётся через creat, сообщения записываются через dprintf, затем дескриптор закрывается вызовом close. Прежнее содержимое hotel.log при новом успешном запуске заменяется.

При ошибочном вводе или ошибке работы с логом программа сообщает о проблеме и возвращает 1. При ошибке ввода новый лог не создаётся. Ctrl+C завершает процесс стандартным механизмом ОС; специального обработчика для сохранения итогов при прерывании нет. Неограниченный режим не реализован.

## 6. Скрипт запуска и проверка ввода

Файл run_tests.sh содержит команды оболочки и три вспомогательные функции. `run_test` проверяет успешное завершение и сравнивает итоговый лог с ожидаемым через `diff`. `check_events` извлекает время, заселения и выезды через `awk` и сравнивает их с файлами в `expected`. `run_error_test` требует код завершения 1 и ожидаемое сообщение об ошибке. При несовпадении скрипт останавливается с ненулевым кодом; сообщение об успехе всех тестов выводится только после всех проверок.

```sh
#!/bin/sh

gcc -std=c11 -Wall -Wextra hotel.c -o hotel || exit 1

mkdir -p results || exit 1

# Запуск обычного теста и сравнение итогового лога с ожидаемым.
# Аргументы: название, сутки завершения, принято, не принято.
run_test() {
    name=$1
    ./hotel < "test_$name.txt" > "results/$name.out" 2>&1 || exit 1
    cp hotel.log "results/$name.log" || exit 1

    printf 'Моделирование завершено на сутках: %s\nВсего приняли клиентов: %s.\nНе успели принять клиентов: %s.\n' \
        "$2" "$3" "$4" > "results/$name.expected.log" || exit 1
    diff -u "results/$name.expected.log" "results/$name.log" || exit 1
    printf 'OK: %s\n' "$name"
}

# В двух сложных сценариях проверяем ещё и порядок событий с их временем.
check_events() {
    name=$1
    awk '
        /^Сутки / { day = $2 }
        /^Администратор заселил/ || /^Клиент [0-9]+ выехал/ {
            print day ": " $0
        }
    ' "results/$name.out" > "results/$name.events" || exit 1
    diff -u "expected/$name.events" "results/$name.events" || exit 1
    printf 'OK: порядок событий %s\n' "$name"
}

# Ошибочный ввод должен завершить программу с кодом 1 и сообщением.
run_error_test() {
    name=$1
    if ./hotel < "test_$name.txt" > "results/$name.out" 2>&1; then
        printf 'ОШИБКА: %s принят как корректный ввод\n' "$name"
        exit 1
    else
        code=$?
    fi
    if [ "$code" -ne 1 ]; then
        printf 'ОШИБКА: %s завершился с кодом %s вместо 1\n' "$name" "$code"
        exit 1
    fi
    grep -F "$2" "results/$name.out" > /dev/null || exit 1
    printf 'OK: %s\n' "$name"
}

run_test cutoff 5 2 1
run_test empty 3 0 2
run_test rooms 2 3 0
run_test minimum 1 1 0
run_test max_rooms 1 100 0
run_test max_queue 100 100 0
run_test max_stay 10001 2 0
run_test max_interval 10000 0 2
run_test queue_priority 5 3 0
check_events queue_priority
run_test simultaneous_checkout 5 5 0
check_events simultaneous_checkout

run_error_test invalid_rooms 'Ошибка: нужно целое число от 1 до 100.'
run_error_test invalid_interval 'Ошибка: нужно целое число от 5 до 10000.'
run_error_test invalid_stay 'Ошибка: нужно целое число от 1 до 10000.'

printf '\nВсе 13 тестов пройдены. Результаты сохранены в results.\n'
```

В каталоге `results` для каждого корректного сценария создаются файлы `<название>.out`, `<название>.log` и `<название>.expected.log`: полный вывод, фактический итог и ожидаемый итог. Для двух сложных сценариев добавляется `<название>.events`. Для ошибочного ввода сохраняется только `.out`; оставшийся от предыдущего запуска `hotel.log` не используется как результат такого теста. Все файлы в `results` создаются при запуске скрипта.

## 7. Использование ИИ и оценка реализации

При разработке я использовал ИИ для поиска и объяснения необходимых функций языка C, разбора ошибок и подготовки тестовых сценариев с файлом запуска. Разбирали последовательность основных циклов. После чего код несколько раз проверил самостоятельно и уверен, что в нем ошибок нет.

Расширенные тестовые наборы и автоматическое сравнение результатов также подготовлены с помощью ИИ. Изменены входные файлы, скрипт; исходный код hotel.c при расширении тестов не изменялся. 

В ходе совместного разбора были внесены следующие исправления:


1. Для каждой даты сначала освобождаются номера и обслуживается очередь. Завершение приёма не прерывает проживание и обслуживание уже принятых клиентов.

2. Разобрали проверки creat, dprintf (что возвращают и как проверять). У dprintf ошибкой является отрицательный результат: успешная запись возвращает положительное число байтов.

3. Добавлены переносы строк в сообщениях. Формулировку «Последний клиент выселился» заменили на более логичную «Моделирование завершено», поскольку в пустом сценарии (test_empty) никто не проживал и первая формулировка теряла смысл.

### Ограничения текущей версии

Программа рассчитана на конечное число клиентов и целые условные сутки. Число номеров и клиентов ограничено 100. Специальное завершение по Ctrl+C с сохранением статистики и неограниченный режим отсутствуют.

Функция ввода считывает не более 127 символов одного токена. Более длинный токен может быть разделён между чтениями, его полное обнаружение и удаление остатка не реализованы. Поэтому проведённые проверки ввода подтверждают обработку обычных коротких ошибочных значений, но не любых произвольных данных.

Фиксированный seed позволяет повторять последовательность rand в одной реализации библиотеки. Совпадение последовательностей между разными платформами не предполагается. В тестах использованы фиксированные интервалы; статистические свойства генератора не исследовались.

### Состав сдаваемых файлов

hotel.c – исходный код программы; run_tests.sh – скрипт; test_*.txt – 13 входных наборов; expected – две эталонные последовательности событий; results – создаваемые скриптом полные выводы, итоговые логи и результаты сравнения. Настоящий отчёт описывает последовательную модель, варианты запуска, результаты тестов и фактические ограничения реализации.
