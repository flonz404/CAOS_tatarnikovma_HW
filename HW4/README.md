## 1. Условие и сценарий

В гостинице ограниченное количество одноместных номеров. Клиенты прибывают через случайные интервалы и запрашивают номер на заданное число суток. Если номера заняты, клиент ждёт в общей очереди FIFO. После выезда гостя номер получает следующий ожидающий.

Сервер выполняет роль администратора: хранит номера и очередь, назначает комнаты и отсчитывает условные сутки. Каждый гость представлен отдельным процессом `hotel_client`. Программы написаны на C и обмениваются сообщениями через TCP/IPv4.

Сервер и клиенты запускаются отдельно, в том числе на разных компьютерах. На сервере используется `poll` и неблокирующие сокеты: данные от разных клиентов обрабатываются по мере поступления. Общая память, семафоры и `fork` не нужны, поскольку состояние гостиницы изменяет только сервер.

До начала моделирования должны подключиться все указанные клиенты. Подключение к серверу и прибытие в гостиницу – разные события. Клиент получает от сервера своё время прибытия и срок проживания, а затем запрашивает номер в нужные условные сутки.

В пределах суток сначала обрабатываются запросы и выезды, затем свободные номера распределяются по очереди. Следующие сутки начинаются после ответов клиентов на события текущих суток. Это сохраняет правильный срок проживания и при нулевой задержке. При одновременном прибытии порядок определяется получением запросов сервером.

Приём открыт до указанного момента, не включая его. После закрытия приёма уже принятые клиенты продолжают ждать и проживать до конца заказанного срока. Очередь вмещает всех клиентов. Один номер занят не более чем одним гостем, а гость занимает только один номер.

## 2. Обмен и вывод

Клиент отправляет номер участника, запрос комнаты, подтверждение заселения, сведения о завершённых сутках и выезде. Сервер отвечает данными клиента, текущим временем, постановкой в очередь, назначением комнаты, подтверждением выезда или отказом.

Сообщение состоит из четырёх 32-битных чисел: типа, времени и двух параметров. Числа передаются в сетевом порядке байтов. Программы учитывают, что TCP может доставить сообщение по частям или объединить несколько сообщений.

- Сервер выводит подключение, полученный запрос, постановку в очередь, назначение номера и его освобождение.
- Клиент выводит только свои события: прибытие, ожидание, заселение, каждые завершённые сутки и выезд либо отказ.

Общего вывода всех событий и клиента-наблюдателя в этой версии нет.

## 3. Сборка и запуск

Команды выполняются из папки `HW4`. Для macOS и Linux:

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic server.c hotel.c -o hotel_server
gcc -std=c11 -Wall -Wextra -Wpedantic client.c hotel.c -o hotel_client
```

Либо через CMake:

```bash
cmake -S . -B build
cmake --build build
```

При сборке через CMake исполняемые файлы находятся в `build`.

Запуск сервера в первом терминале:

```bash
./hotel_server 127.0.0.1 5000 < tests/test_cutoff.txt
```

После сообщения «Сервер готов» запустить клиентов во втором терминале:

```bash
./hotel_client 127.0.0.1 5000 1 &
./hotel_client 127.0.0.1 5000 2 &
./hotel_client 127.0.0.1 5000 3 &
wait
```

`&` запускает программу в фоне, `wait` ожидает их завершения. Для раздельного просмотра вывода каждую команду клиента можно выполнить в своём терминале без `&`.

Для работы на нескольких компьютерах сервер запускается так:

```bash
./hotel_server 0.0.0.0 5000 < tests/test_cutoff.txt
```

Клиенты указывают реальный IPv4-адрес компьютера с сервером, например:

```bash
./hotel_client 192.168.1.10 5000 1
```

В примере `192.168.1.10` нужно заменить на адрес сервера. Между компьютерами должен быть доступен указанный TCP-порт. `127.0.0.1` подходит только для запуска на одном компьютере, а `0.0.0.0` используется сервером для прослушивания всех IPv4-интерфейсов.

## 4. Исходные данные и завершение

Сервер читает числа из терминала или файла в прежнем порядке:

| Данные | Допустимые значения |
| --- | --- |
| Количество номеров | 1–100 |
| Количество клиентов | 1–100 |
| Минимальный и максимальный интервалы прибытия | 0–10000, максимум не меньше минимума |
| Момент прекращения приёма | 1–10000 суток |
| Задержка между условными сутками | 0–5 секунд |
| Срок проживания каждого клиента | 1–10000 суток |

Интервалы генерируются через `rand` с `srand(1)` и прибавляются ко времени предыдущего прибытия. Нулевой интервал допускает одновременное прибытие. Последовательность воспроизводима в рамках одной реализации libc.

Номер клиента в командной строке – число от 1 до количества клиентов. Повторное подключение под занятым номером отклоняется. Ошибка ввода завершает программу с кодом 1.

Клиент завершает работу после подтверждённого выезда или отказа. Сервер завершает работу, когда все клиенты обслужены либо не приняты. Успешное завершение имеет код 0.

По умолчанию сервер ждёт подключения всех участников 60 секунд. Время можно изменить третьим аргументом, например `./hotel_server 127.0.0.1 5000 120`. Допустимо 1–300 секунд. Клиент ждёт первое сообщение или очередное событие не более 360 секунд; сбор оставшейся части сообщения ограничен 10 секундами.

При обрыве связи с действующим клиентом, неверном сообщении или отсутствии ответа в течение 10 секунд сервер останавливает модель и уведомляет остальных. Так незавершённое проживание не считается успешным. Для новой попытки программы запускаются заново.

`Ctrl+C` и `SIGTERM` завершают выбранную программу с кодом 130 или 143. Остановка сервера приводит к завершению клиентов; отключение действующего клиента приводит к остановке сервера. Сокеты закрываются. Остальные участники завершаются с кодом 1, поскольку обслуживание прервано.

## 5. Проверки

Для автоматических тестов нужен Python 3:

```bash
sh run_tests.sh
```

Проверяются обычные сценарии, FIFO, одновременные события, граница закрытия приёма, 100 номеров и клиентов, максимальный срок проживания, неверные данные, занятый порт, повторные подключения, сообщения по частям, обрывы связи и сигналы завершения.

На macOS и Linux пройдено **по 40 из 40 тестов**. Сборка с `-Wall -Wextra -Wpedantic -Werror` прошла на обеих системах. Дополнительно проверен сервер и три клиента в четырёх отдельных Docker-контейнерах, соединённых сетью: сценарий завершился успешно.

Вывод сохраняется раздельно для сервера и каждого клиента в папке `results`; краткие результаты – в `results/summary.json`. Linux-результаты проверки находятся в `results/linux`, сетевого запуска – в `results/distributed`. Исполняемые файлы и результаты исключены из Git.

В тесте `test_cutoff.txt` один номер и три клиента. Первый заселяется на сутках 1 и выезжает на сутках 4. Второй прибывает на сутках 2, ждёт и проживает с суток 4 до суток 5. Третий должен прибыть на сутках 3, когда приём уже закрыт, поэтому получает отказ. Сервер завершает обслуживание на сутках 5.
