# HW4. Клиент-серверная модель гостиницы

**Дисциплина:** АКОС.

**Выполнил:** Татарников Максим Александрович, БПИ-252.

**Вариант:** №12 – Задача о гостинице.

**Реализованный уровень:** 6–7 баллов. Сохранён запуск без наблюдателя на 4–5 баллов.

## 1. Условие и сценарий

Гостиница имеет ограниченное число одноместных номеров. Клиенты прибывают через случайные интервалы, заселяются на заданный срок или ждут свободного номера в очереди FIFO. После закрытия приёма уже принятые гости обслуживаются до конца. Один номер занимает только один гость.

Сервер играет роль администратора, каждый клиент – отдельный процесс. Программы написаны на C и взаимодействуют по TCP/IPv4 через неблокирующие сокеты и `poll`. Они могут работать на разных компьютерах. Модель запускается после подключения всех клиентов; гости прибывают в назначенные условные сутки. Следующие сутки начинаются после обработки текущих событий.

## 2. Обмен и вывод

- Сервер показывает запросы, очередь, назначение и освобождение номеров.
- Клиент показывает своё прибытие, ожидание, заселение, каждые сутки проживания и выезд или отказ.
- `hotel_observer` получает все события и итог, поэтому позволяет следить за гостиницей в одном окне.

Сообщение содержит четыре 32-битных числа в сетевом порядке байтов. Частичное получение и отправка учитываются. Для наблюдателя сервер дополнен отправкой событий, а общая функция подключения вынесена в `hotel.c`.

## 3. Сборка и запуск

Из папки `HW4` на macOS или Linux:

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic server.c hotel.c -o hotel_server
gcc -std=c11 -Wall -Wextra -Wpedantic client.c hotel.c -o hotel_client
gcc -std=c11 -Wall -Wextra -Wpedantic observer.c hotel.c -o hotel_observer
```

Либо через CMake; тогда программы находятся в `build`:

```bash
cmake -S . -B build
cmake --build build
```

Первый терминал – сервер:

```bash
./hotel_server 127.0.0.1 5000 < tests/test_cutoff.txt
```

После сообщения «Сервер готов» во втором терминале – наблюдатель:

```bash
./hotel_observer 127.0.0.1 5000
```

После сообщения «Наблюдатель подключён» в третьем терминале – клиенты:

```bash
./hotel_client 127.0.0.1 5000 1 &
./hotel_client 127.0.0.1 5000 2 &
./hotel_client 127.0.0.1 5000 3 &
wait
```

`&` запускает процесс в фоне, `wait` ждёт завершения. Для режима на 4–5 баллов наблюдатель не запускается.

Для работы по сети серверу указывается адрес `0.0.0.0`, клиентам и наблюдателю – реальный IPv4-адрес сервера. Порт должен совпадать и быть доступен между компьютерами. `127.0.0.1` используется для запуска на одном компьютере.

## 4. Исходные данные и завершение

Сервер читает числа из терминала или файла в следующем порядке:

| Данные | Диапазон |
| --- | --- |
| Количество номеров | 1–100 |
| Количество клиентов | 1–100 |
| Минимальный и максимальный интервалы прибытия | 0–10000, минимум ≤ максимум |
| Момент прекращения приёма | 1–10000 суток, сама граница не включается |
| Задержка между сутками | 0–5 секунд |
| Срок проживания каждого клиента | 1–10000 суток |

Интервалы создаются через `rand` с `srand(1)`; нулевой интервал допускает одновременное прибытие. Номера клиентов уникальны и задаются от 1 до их общего количества.

Поддерживается один наблюдатель, подключаемый до старта модели. Его отключение или переполнение буфера не останавливает гостиницу. Сервер ждёт гостей 60 секунд; ожидание можно задать третьим аргументом от 1 до 300 секунд, например `./hotel_server 127.0.0.1 5000 120`.

После обслуживания всех гостей и отказа опоздавшим программы завершаются с кодом 0. Ошибки ввода, связи или отсутствие ответа действующего клиента за 10 секунд приводят к завершению с кодом 1. `Ctrl+C` и `SIGTERM` дают коды 130 и 143; остановка сервера или действующего клиента прекращает моделирование для остальных участников. Сокеты закрываются.

## 5. Проверки

Запуск тестов с Python 3:

```bash
sh run_tests.sh
```

На macOS и Linux пройдено **по 62 теста**: 40 прежних и 22 проверки наблюдателя. Проверены FIFO, границы данных, 100 клиентов, максимальный срок проживания, сетевые ошибки, сигналы и полнота общего вывода. Строгая сборка с `-Werror` и сетевой запуск в пяти отдельных Docker-контейнерах прошли успешно.

В `test_cutoff.txt` первый гость живёт с суток 1 до 4, второй – с 4 до 5, третий получает отказ при закрытии приёма на сутках 3. Наблюдатель выводит итог:

```text
Моделирование завершено на сутках: 5.
Завершили проживание: 2. Не приняты: 1.
```

Вывод программ и результаты тестов находятся в `results`, Linux-проверок – в `results/linux`, сетевого запуска – в `results/distributed_observer`. Эти файлы и исполняемые программы исключены из Git.
